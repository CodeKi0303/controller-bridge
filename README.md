# Controller Bridge

Android에 연결한 USB·Bluetooth 게임패드의 입력을 원하는 이름·ID·버튼 배치의 가상 컨트롤러로 전달합니다. 앱별로 출력 프로필을 저장하고 실행할 수 있습니다.

## 설치

[Releases](https://github.com/CodeKi0303/controller-bridge/releases)에서 `controller-bridge-*-release.apk`를 받아 설치하세요. 업데이트할 때는 기존 앱을 지우지 않고 같은 서명의 APK를 설치합니다.

- Android 11 이상
- USB 또는 Bluetooth 게임패드
- 무선 디버깅을 사용할 수 있는 Wi-Fi 연결

루팅은 필요하지 않습니다. Bluetooth 패드도 입력 변환에는 디버깅 권한이 필요합니다. 기기 제조사의 입력 장치 접근 정책에 따라 사용할 수 없는 환경이 있습니다.

## 처음 연결하기

1. Android 개발자 옵션에서 **무선 디버깅**을 켭니다.
2. 앱의 **연결 준비 → 처음 연결하는 방법 → 알림에서 페어링 시작**을 누르고 알림을 허용합니다.
3. Android 설정에서 **무선 디버깅 → 페어링 코드로 기기 페어링**을 엽니다.
4. 코드 창을 닫지 않은 채 알림창을 내립니다. Controller Bridge 알림의 **포트·코드 입력**에 `페어링 포트`와 `6자리 코드`를 공백으로 구분해 입력합니다. 예: `37123 001234`.
5. 페어링이 끝나면 무선 디버깅 첫 화면의 **IP 주소 및 포트**에서 연결 포트를 확인합니다. 앱에 **연결 포트**를 입력하고 **입력 서비스 시작 → 준비 후 계속**을 누릅니다.

**페어링 포트와 연결 포트는 서로 다릅니다.** 이미 페어링했다면 새 코드 없이 연결 포트를 확인하고 입력 서비스만 시작하면 됩니다. 재부팅하거나 무선 디버깅을 다시 켜면 연결 포트가 달라질 수 있습니다.

알림 입력을 사용할 수 없다면 **연결 관리 · 다른 입력 방법 → 분할 화면에서 직접 입력**을 사용하세요. 기존 Shizuku를 이용하려면 **앱 설정 → 고급 연결 설정**에서 연결 방식을 변경합니다.

## 사용하기

1. 게임패드를 연결합니다.
2. **게임**에서 사용할 앱과 출력 프로필을 선택합니다. 목록에 없다면 **게임 추가**에서 찾습니다.
3. **게임 실행**을 누릅니다. 컨트롤러가 여러 개면 사용할 입력 장치를 선택합니다.
4. 사용을 마치면 **변환 중지** 또는 알림의 **입력 종료**를 누릅니다.

출력 프로필은 **PS4 · PS5 · Xbox · Kishi Ultra**입니다. 각 프로필의 장치 이름과 ID, 버튼 배치를 편집할 수 있습니다. 같은 프로필을 사용하는 앱에는 편집 내용이 공통 적용됩니다.

가상 컨트롤러를 추가하는 방식이며 실제 패드의 Bluetooth 이름이나 펌웨어는 바꾸지 않습니다. 프로필 지원 여부는 사용하는 앱에 따라 다릅니다.

## 버튼 매핑

1. **프로필 → 편집**에서 출력할 버튼을 선택합니다.
2. 입력에 사용할 컨트롤러를 고릅니다. 변환 중이면 먼저 **변환 중지**를 누릅니다.
3. 실제 패드의 버튼 하나를 눌렀다 놓습니다.
4. 필요한 버튼을 지정한 뒤 상단의 **저장**을 누릅니다.

PS 프로필에는 `× / A`, `○ / B`, `□ / X`, `△ / Y`를 함께 표시합니다. **연결 해제**는 해당 출력 연결을 지우고, **사용 안 함**은 직접 누른 입력 버튼을 끕니다. 스틱·방향키·트리거는 원본 컨트롤러 배치 설정에서 조정합니다.

## 입력 확인

**컨트롤러**에서 장치를 선택하면 이름·ID와 입력 상태를 확인할 수 있습니다. **프로필 적용 후 테스트**로 가상 출력을 만들고 해당 장치를 선택하세요. 누르는 버튼과 움직이는 스틱·트리거가 붉게 표시되며 동시 입력도 확인할 수 있습니다.

## 문제가 생겼을 때

- **입력 서비스가 시작되지 않음:** 무선 디버깅이 켜져 있는지, 현재 연결 포트가 맞는지 확인합니다.
- **패드가 목록에 없음:** 연결을 다시 확인하고 앱에서 장치 목록을 갱신합니다.
- **앱에서 입력되지 않음:** 컨트롤러 테스트에서 가상 출력의 입력을 먼저 확인한 뒤 다른 출력 프로필을 선택합니다.
- **버튼 위치가 다름:** 프로필 편집에서 출력 버튼을 선택하고 실제 버튼으로 다시 지정합니다. 연결 방식이나 패드를 바꾸면 배치가 달라질 수 있습니다.
- **기존 APK 위에 설치되지 않음:** 서명이 다른 설치본은 덮어쓸 수 없습니다. 현재 앱에는 설정 내보내기가 없으므로 필요한 설정을 기록한 뒤 설치본을 변경하세요.

한 번에 입력 장치 하나를 사용합니다. 여러 장치의 입력 결합과 진동 반환은 지원하지 않습니다. Android가 앱에 전달하지 않는 시스템 버튼은 매핑할 수 없습니다.

## 빌드

JDK 17 또는 21, Android SDK 35, Build Tools 35.0.0, NDK 23.1.7779620이 필요합니다. Gradle 래퍼를 사용합니다.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
```

네이티브 페어링 검사까지 실행하려면 호스트 C 컴파일러와 Python 3을 준비합니다.

```sh
bash scripts/build-adb-host-test-library.sh
python3 scripts/adb-pairing-reference.py
./gradlew -PadbNativeTestDir="$PWD/.tools/adb-host-tests" testDebugUnitTest lintDebug assembleDebug
```

`adbNativeTestDir`를 생략하면 네이티브 페어링 검사는 건너뜁니다. Windows에서는 `scripts/build.ps1`에 `-JdkHome`, `-SdkRoot`, 필요하면 `-NdkRoot`를 지정할 수 있습니다.

`assembleRelease`는 서명 전 APK를 생성합니다. 서명 키는 저장소 밖에서 관리하며, 업데이트에는 같은 키를 사용하세요. APK를 재배포할 때는 같은 버전의 앱 소스와 Releases의 `dependency-sources` 전체 소스 ZIP 두 개를 함께 제공해야 합니다.
